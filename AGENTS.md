# AGENTS.md

Инструкции для агентов, работающих с репозиторием `mmwtl/xe`.

## Стиль работы с владельцем

- Отвечай прямо и конкретно. Не соглашайся автоматически и не хвали идеи из
  вежливости.
- Отделяй подтверждённые факты от предположений. Указывай риски, противоречия,
  скрытые издержки и степень уверенности.
- Если предложение непрактично или основано на неверной предпосылке, скажи об
  этом и предложи лучший вариант.
- Пользовательский интерфейс, сообщения об ошибках и документация проекта
  преимущественно русскоязычные.

## Что это за проект

`ХЕ.СЧЁТ` — небольшое русскоязычное PWA на Next.js для приблизительной оценки
углеводов и хлебных единиц по описанию блюда и/или фотографиям. Анализ выполняет
Gemini через серверный API-маршрут. Приложение не является медицинским изделием.

Ключевые продуктовые ограничения:

- в приложении всегда используется формула `1 ХЕ = 12 г углеводов`;
- результат приблизительный и не должен превращаться в рекомендацию по дозе
  инсулина, лекарствам или другим медицинским действиям;
- один расчёт может содержать описание и до трёх фотографий одного блюда;
- все фотографии одного расчёта отправляются в один inference-запрос и не
  считаются отдельными порциями;
- аккаунтов и реляционной серверной базы данных нет;
- история хранится только в IndexedDB текущего браузера, включая ответы, ошибки
  и прикреплённые фото;
- при настроенном private Vercel Blob новые запросы, ответы, ошибки, метаданные
  фото и компактное WebP-превью пишутся в защищённый админ-журнал;
- фотографии отправляются Gemini только после явного нажатия
  `Рассчитать ХЕ`.

## Стек и команды

- Next.js 16 App Router, React 19, TypeScript в strict-режиме.
- Node.js `>=22.13.0`, пакетный менеджер — npm.
- Установка: `npm ci`.
- Разработка: `npm run dev`.
- Разработка с доступом из локальной сети: `npm run dev:mobile`.
- Локальный HTTPS для проверки PWA/камеры: `npm run dev:https`.
- Проверка без внешнего API: добавить `GEMINI_MOCK=1` в `.env.local`.
- Обязательные проверки: `npm run check` и `npm run build`.
- Production-запуск вручную: `npm run build && npm start`.
- `./start.sh` — macOS-ориентированный безопасный перезапуск production-сервера
  в фоне. Он собирает проект, не убивает чужой процесс на занятом порту, хранит
  PID в `.xe-schet.pid`, а лог — в `xe-schet.log`. Порт можно задать через
  `PORT=3001 ./start.sh`.

Автоматизированного unit/integration test suite сейчас нет. Не сообщай, что
«тесты прошли», если были выполнены только lint, typecheck и build; перечисляй
проверки точно.

## Карта кода

- `app/page.tsx` — единственная страница: шапка, вводный блок, `Analyzer`,
  предупреждение и footer.
- `app/components/analyzer.tsx` — основной клиентский компонент: описание,
  камера/галерея, превью, отправка запроса, результат и интерфейс истории.
- `app/api/analyze/route.ts` — серверная граница доверия: чтение `FormData`,
  ограничения загрузки, проверка формата, mock-ответ, цепочка моделей и перевод
  ошибок в HTTP/JSON, а также неблокирующая запись аудита.
- `app/admin/` — защищённые паролем login и адаптивный журнал запросов.
- `app/api/admin/` — серверная сессия и чтение private Blob для админки.
- `lib/admin-auth.ts` — подписанная HttpOnly-сессия администратора.
- `lib/audit-storage.ts`, `lib/audit-types.ts` — Vercel Blob-аудит и его типы.
- `lib/gemini.ts` — формирование мультимодального prompt, structured output,
  нормализация ответа и окончательный расчёт углеводов/ХЕ.
- `lib/model-fallback.ts` — последовательный fallback моделей только для `429`.
- `lib/image-mime.ts` — определение JPEG/PNG/WebP/HEIC/HEIF по сигнатуре.
- `lib/types.ts` — типы нормализованного ответа API.
- `lib/history.ts` — IndexedDB `xe-schet`, store `analysis-history`, чтение,
  запись и полная очистка локальной истории.
- `app/components/pwa-register.tsx` — регистрация service worker только в
  production и удаление старого project-specific worker/cache в development.
- `app/components/install-button.tsx` — браузерный PWA install prompt и
  определение standalone-режима.
- `app/manifest.ts`, `public/sw.js`, `public/icon-*.png` — PWA-манифест, offline
  shell и иконки.
- `app/globals.css` — все стили приложения; CSS Modules и UI-библиотеки не
  используются.
- `.env.example` — полный публичный шаблон переменных окружения.
- `.github/workflows/ci.yml` — `npm ci`, `npm run check`, `npm run build` на
  Node.js 22.13.

## Поток одного расчёта

1. `Analyzer` собирает `description` и повторяющееся поле `photos` в `FormData`.
2. `POST /api/analyze` повторно проверяет вход. Клиентская проверка нужна для UX,
   но не считается защитной границей.
3. API определяет тип изображения по содержимому и передаёт все фото вместе с
   одним текстовым prompt в `analyzeMeal`.
4. Gemini возвращает JSON по схеме только с оценками порций и углеводов на
   100 г.
5. `normalizeAnalysis` сам вычисляет углеводы продукта, итог и ХЕ. Не доверяй
   итоговой арифметике модели и не переноси расчёт `÷ 12` в prompt как
   единственный источник результата.
6. Клиент показывает ответ и сохраняет завершённый запрос в IndexedDB. Ошибочные
   ответы тоже являются записями истории.

## Инварианты API и загрузки

- `GEMINI_API_KEY` используется только на сервере. Никогда не добавляй ключ в
  `NEXT_PUBLIC_*`, клиентский код, Git, логи, issue или скриншоты.
- `ADMIN_PASSWORD`, `ADMIN_SESSION_SECRET` и `BLOB_READ_WRITE_TOKEN` также
  являются серверными секретами и не должны попадать в клиент или Git.
- Максимум: 3 фото, 10 МБ на файл, 14 МБ суммарно, описание до 2000 символов.
  При изменении лимитов синхронно обновляй клиент, API, README и тексты ошибок.
- Поддерживаемые форматы: JPEG, PNG, WebP, HEIC и HEIF.
- Серверная проверка сигнатуры обязательна. Нельзя доверять только `File.type`
  или расширению файла.
- Fallback-моделей разрешён только после `429 / RESOURCE_EXHAUSTED`. Ошибки
  ключа, сети, формата или обработки нельзя маскировать переключением модели.
- Цепочка берётся из `GEMINI_MODEL` и `GEMINI_FALLBACK_MODELS`; значения по
  умолчанию заданы в API-маршруте. Названия и доступность моделей меняются —
  перед их заменой сверяй актуальную официальную документацию Gemini.
- Ответ API и результаты истории используют camelCase из `lib/types.ts`;
  snake_case Gemini должен оставаться внутри слоя нормализации.

## История и совместимость данных

- История локальная, без синхронизации между устройствами.
- Админ-журнал не является пользовательской историей: он содержит только новые
  серверные обращения после подключения private Vercel Blob и читается через
  авторизованный server API.
- Текущая запись использует `photos` и `photoNames`. Поля `photo` и `photoName`
  сохранены для чтения старых записей с одним фото — не удаляй их без миграции.
- Запись должна считаться сохранённой только после завершения IndexedDB
  transaction.
- При изменении структуры IndexedDB проектируй upgrade/migration и увеличивай
  `DATABASE_VERSION`; не ломай молча существующую историю пользователя.
- Object URL для выбранных и исторических фото необходимо освобождать через
  `URL.revokeObjectURL`.
- Полная очистка истории должна оставаться явным действием с подтверждением.

## UX, который уже согласован

- Не возвращай отдельные вкладки «по фото» и «по описанию»: используется одно
  поле, к которому можно добавить фото.
- На мобильном калькулятор должен начинаться в первом экране; история идёт
  отдельным блоком ниже него.
- Не возвращай удалённый рекламный блок «Локальный интерфейс».
- Для фотографий нужны компактные превью в строку и отдельная кнопка удаления
  каждого фото.
- Съёмка и выбор готовых файлов — два отдельных действия. Камера вызывается
  скрытым input с `capture="environment"`; галерея остаётся отдельным multiple
  input.
- Числа и даты форматируются для `ru-RU`.
- Сохраняй медицинское предупреждение видимым и не заменяй точные заявления о
  приватности расплывчатым «всё локально»: запрос и фото уходят в Gemini, а
  история хранится локально.

## PWA и кэш

- Service worker регистрируется только в production.
- В development `PwaRegister` удаляет только worker `/sw.js` и кэши с префиксом
  `xe-schet-shell-`. Не очищай все service workers или все browser caches
  безусловно.
- Старый service worker уже вызывал hydration mismatch и показывал устаревший
  интерфейс. При изменении offline shell/стратегии обновляй `CACHE_NAME` и
  проверяй чистый origin либо новую browser-сессию.
- `public/sw.js` не должен кэшировать `/api/*` и `/_next/*`.
- Камера и установка PWA требуют secure context (`localhost` или HTTPS).
  Desktop file chooser не доказывает, что реальная камера открывается на
  Android/iPhone.

## Проверка изменений

Минимум перед завершением любой доработки:

```bash
npm run check
npm run build
git status --short
```

Для изменений интерфейса дополнительно проверь настоящий рендер:

- мобильный viewport примерно `390x844`;
- desktop примерно `1280x900`;
- отсутствие горизонтального переполнения;
- ошибки и предупреждения в browser console;
- калькулятор виден до истории;
- состояние без фото, 1–3 фото, удаление фото, ответ и ошибка;
- история после reload и просмотр старой записи.

Для API используй `GEMINI_MOCK=1`, если реальный Gemini не является предметом
проверки. Реальный API-запрос выполняй только когда он нужен для задачи и ключ
уже настроен локально; никогда не выводи значение ключа.

Для камеры окончательная проверка — физический Android/iPhone по HTTPS. Для PWA
проверяй production build, manifest, service worker update и установленный
режим, а не только dev-сервер.

## Git и поставка

- В начале работы всегда смотри `git status --short --branch`, текущую ветку и
  незакоммиченные изменения. Не перезаписывай чужую работу.
- Предпочтение владельца: каждая законченная доработка фиксируется отдельным
  понятным коммитом. Не объединяй независимые изменения в один коммит.
- Коммить только относящиеся к задаче файлы и только после проверок. Push,
  merge, PR и деплой не следуют автоматически из требования сделать коммит —
  выполняй их по явному запросу.
- Обычно новая функция делается в отдельной ветке от актуального `main`; не
  создавай новую ветку поверх случайно оставшейся feature-ветки без проверки.
- Remote: `git@github.com:mmwtl/xe.git`.
- Production-размещение рассчитано на Vercel с серверной переменной
  `GEMINI_API_KEY`. GitHub Pages не подходит: `/api/analyze` требует Node.js
  runtime, а перенос ключа Gemini в браузер недопустим.

## Известные ловушки и технический долг

- Клиент сейчас проверяет `File.type` до отправки, а сервер умеет распознавать
  HEIC/HEIF по сигнатуре. Safari/браузер может отдать HEIC с пустым MIME или
  `application/octet-stream`, и тогда корректный файл будет отклонён клиентом.
  При следующей доработке uploader нужно согласовать с серверной проверкой и
  подтвердить поведение на настоящем iPhone.
- Автоматических тестов нет; критическая логика fallback, MIME detection,
  нормализации Gemini и IndexedDB заслуживает unit/integration tests.
- `analyzer.tsx` объединяет много обязанностей и уже велик. При расширении
  отделяй загрузку фото, расчёт и историю по компонентам/hooks, не создавая
  дублирующее состояние.
- В `package.json` есть security overrides для `postcss` и `sharp`. Не удаляй их
  без повторного `npm audit --omit=dev`, сборки и проверки совместимости.
- `npm audit fix --force` ранее пытался перевести ESLint на несовместимый major и
  ломал lint. Не применяй его автоматически; оценивай runtime и dev-зависимости
  отдельно.
- Не обещай точность массы или состава сложного блюда по одному фото. Если
  продуктовая задача потребует более надёжного медицинского результата, нужен
  подтверждаемый пользователем состав/вес и источник пищевой ценности, а не
  только свободная оценка LLM.
